## Artifact and action order

`bootstrap.manifest.v1.json` pins bootstrap v2 UTF-8 LF template bytes by SHA-256;
`PRODUCTION_BOOTSTRAP_V2.sql` is its sole ordered action. Loader uses fixed paths.
V1 remains a historical rehearsal artifact, not the recommended first-write entry.
The application `manifest.v1.json` remains separate and unchanged.

Bootstrap: BEGIN; bounded local timeouts; advisory transaction lock; database/PG18
guard; admin sec_admin schema + identity table; saved UUID INSERT; distinct restricted
LOGIN roles; revoke PUBLIC database/schema privileges; grant CONNECT; migrator-owned
sec_app; schema USAGE and identity SELECT; per-migrator default PUBLIC revocations;
admin bootstrap_history + version/template checksum/COMPLETE INSERT; COMMIT.
All these actions, including role creation, are transactional in PG18. No application
tables or application migration history are created by bootstrap.
Every CREATE is intentionally non-idempotent: duplicate bootstrap is refused.
Never use IF NOT EXISTS to silently adopt unknown objects.

credential remains offline, never Netlify runtime.

## Recovery and authorization boundaries

Lock timeout 5s; statement 10s; idle-in-transaction 15s; total transaction 30s.
Pre-COMMIT error: ROLLBACK / disconnected transaction rollback, no terminal success.
Success history is in the same transaction as roles/identity/schema; no outside
process can legitimately label COMPLETE before COMMIT is confirmed and READ ONLY
verification succeeds. A failed attempt has no persisted terminal record; keep a
sanitized operator event outside the repository (no credential/UUID dump).
COMMIT acknowledgement loss: UNKNOWN, never assume rollback or automatically replay.
Fresh separately authorized READ ONLY verification checks the pre-recorded UUID,
bootstrap history version/checksum, roles, ownership and privileges. Matching full
state means committed; absent full state means assess rollback; any partial/conflict
state requires STOP and reviewed recovery. No automated reconciler is supplied.
Template checksum protects immutable source, not secret-substituted bytes; never
store password-bearing rendered SQL or its operational dump in Git/history.

Readiness approval is NOT WRITE approval. Before first bootstrap, separately
approve exact target, v2 artifact/checksum, UUID procedure, privileges and recovery.
Migration is a later separate approval: use dedicated migrator Direct credential,
manifest-only SQL, all four existing migration gates, bounded temporary database
CREATE grant revoked on every outcome, followed by READ ONLY verification. No
startup bootstrap/migration and no application runtime wiring is authorized.
